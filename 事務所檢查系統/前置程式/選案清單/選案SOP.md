# 事務所檢查選案 SOP（權數表排序法）

適用：年度事務所檢查之受查客戶選案（首例：115 年度檢查安永，114Q4 資料）。
核心工具：`make_selection_list.py`（本資料夾；**改動前先讀腳本 docstring 的「已知陷阱」**）。

## 選案邏輯：三層漏斗

```
第1層 建母體（機器） listdata auditor 快照 篩事務所 → 全部受查客戶（含公發/興櫃）
第2層 分數排序（機器） join 官方權數表 → 權數總計高→低，無分數者沉底不刪
第3層 人工圈案（檢查員）門檻/新承接/換所/臨界戶/內部訊號 → 圈定名單
之後 → 逐家跑勤前分析產線（FR_extract pre-inspection skill）
```

**分工鐵律**：前兩層全自動、可重現、可驗證；第三層永遠是人的判斷，不寫進程式。

## 執行步驟（每年度一次）

1. **listdata 產 auditor 快照**（辦公室或本機）：
   `run_all.ps1 -Year 114 -Season 04` → `114Q04_auditor_YYYYMMDD.xlsx`
   （這是母體唯一權威來源＝MOPS 申報當時的簽章會計師/意見/日期。**不可**用「最新狀態」API 代替，
   否則已換所客戶會漏、新客戶會提早混入。）
2. **取得該季權數表**放進 `權數表\` 資料夾：
   - 證交所「本國上市公司平時管理權數統計表」（xlsx）
   - 櫃買中心「上櫃公司平時管理權數統計表」（xls，有開檔密碼，通常寫在檔名）
3. **確認 district.csv 是最新**（listdata 與 projects\mops-daily 兩份同步）。
4. **跑腳本**：
   ```
   python make_selection_list.py --year 114 --season 04 --firm 安永
   ```
   產出 `114Q4_選案清單_安永.xlsx`（4 sheets：說明／清單／內嵌上市權數表／內嵌上櫃權數表）。
5. **開檔驗證（30 秒）**：
   - 「檢核(與原表總計差)」欄**全為 0**（≠0 會自動標紅）＝清單分數與官方原始表勾稽相符。
   - 抽 1–2 家「主要扣分項目」分數相加＝權數總計。
6. **人工圈案**，考量：
   - 分數門檻（如 ≥100 分）或 top N
   - 備註欄「新承接（審計510 期初餘額）」——權數表抓不到的風險，優先考慮
   - 同分臨界戶人工裁決（例：114 安永 福裕/凱碩同 117 分，凱碩另有新承接訊號）
   - 無權數沉底者另行考量：金融業（另有監理）、上市 KY（需外國企業版權數表）
   - **疊加內部訊號**：檢舉、前次檢查缺失、監視名單——不在權數模型內
7. 圈定後 → 逐家跑勤前分析（`FR_extract` repo 的 pre-inspection skill）。

## 為什麼可信（驗證設計）

- 分數不落地為死數字：清單權數欄＝INDEX+MATCH 公式**即時取自檔內內嵌的官方原始表**，
  檢核欄＝總計−原表總計，開檔重算後全 0 才算通過。
- 主要扣分項目由原始表分項欄直接彙整，**分項相加＝權數總計**（114 安永 205 家零不符實測）。
- v2 上線驗證（2026-07-16）：與獨立管線（權數排序 xlsx＋EY_risk_ranking.csv）比對，
  17 家立本順序/分數全符、208 家安永分數零誤差。

## 已知陷阱（詳見腳本 docstring，這裡列最致命的）

1. **權數表欄 84 表頭誤標「權數總計」，實為非財務合計**；真總計在欄 85（合併表頭，唯讀模式讀不到）。
   兩市場檔案都有此問題。→ 取數一律用固定索引（0-indexed 65/83/84），不要按表頭文字定位。
2. 公司代號型別：申報快照是文字（證券期貨商含前導零），權數表是數字。
3. 證券期貨商雙申報重複兩列＝正常；證交所版權數表**不含上市 KY**。
4. Google Drive 網頁預覽不算公式（權數欄看似空白）＝正常，用 Excel 開。
5. MOPS EPS/淨值有快取 `fin_cache_*.json`；換季重抓、同季重跑不打 MOPS。
